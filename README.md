# ONE FOR ALL: College Portal

A full-stack college portal. A public website shows the college to visitors, and a closed, role-based portal lets **students**, **teachers** and **admins** sign in. Its centrepiece is a **Student-Teacher Doubt (Query) Portal**.

Built by **Team Anti Gravity** as a Web Development Lab project.

---

## 1. Project Overview & Live Features

### Public website
Open to everyone, no login needed.

| Page | What it shows |
|---|---|
| **Home** (`index.html`) | Hero, statistics, announcements, and campus cards with a **blue-gradient hover-reveal**: each card shows a gradient, and the campus photo fades in when you hover over it |
| **About** | History, vision, mission, leadership. The "Main campus" card uses the same hover-reveal |
| **Academics** | Programs with a filter, and admission steps |
| **Facilities** | Labs, library, sports, hostel and amenities |
| **Gallery** | Full photo grid with **category filters** (All, Campus, Events, Sports, Labs) and a full-screen lightbox. All photos are shown directly, no hover needed |
| **Contact** | Enquiry form, map and FAQ |

### Closed portal (Role-Based Access Control)
- Three roles: **Student**, **Teacher**, **Admin**. There is **no public sign-up**: only an admin can create accounts.
- Portal IDs are generated by the system: `STD0001`, `TEA0001`, `ADM0001`.
- Each role has its own dashboard. A route guard (`auth.js`) sends anyone with the wrong role back to their own dashboard, and the server checks the role again on every API call.

### Account security flow
- **Forced first-login password change.** Every new or reset account gets a temporary password and must set a strong one before using the portal.
- **Admin dashboard:** create users (the next free ID is assigned automatically), search and filter users, **suspend / re-enable** accounts, and **reset passwords**. A temporary password is shown once and never stored in plain text.

### Student-Teacher Doubt / Query Portal
- **Students** post a question with a *subject* and a *question* body, then see all their own questions with status and the teacher's reply.
- **Teachers** see an inbox with **Open / Answered / All** tabs (oldest unanswered question first), read the question and reply. A teacher can edit their own reply later.
- Live counters on both dashboards, "Load more" paging, and protection against two teachers answering the same question at once.
- A student only ever sees their own questions. Limit: 10 new questions per student per hour.

## 2. Tech Stack

| Layer | Technology |
|---|---|
| **Frontend** | Pure **HTML5, CSS3 and vanilla JavaScript** in `public/` (no framework). GSAP and Shery.js (CDN) for homepage animations |
| **Backend** | **Node.js** and **Express.js** in `server/` |
| **Database** | **MongoDB** with **Mongoose** |
| **Security** | **JWT** (`jsonwebtoken`), **`bcryptjs`** password hashing, **`helmet`** security headers, **`cors`**, **`express-rate-limit`** (login, password and query endpoints) |

Other notes
- Tokens are checked against the database on every request, so a suspended account or a changed role takes effect immediately.
- All user text is placed on pages with `textContent`, so questions like `<script>` appear as plain text and can never run.

### Main API endpoints

| Method | Endpoint | Who | Purpose |
|---|---|---|---|
| POST | `/api/auth/login` | anyone | Sign in with ID, password and role |
| POST | `/api/auth/change-password` | signed-in user | Change password (forced on first login) |
| POST | `/api/auth/forgot-password` | anyone | Forgot-password request (rate limited) |
| GET | `/api/me` | signed-in user | Who am I? (used by the route guard) |
| GET | `/api/admin/users` | admin | List users (search, filter, paging) |
| POST | `/api/admin/users` | admin | Create a user with the next free ID |
| PATCH | `/api/admin/users/:userId/status` | admin | Suspend or re-enable an account |
| POST | `/api/admin/users/:userId/reset-password` | admin | Issue a new temporary password |
| POST | `/api/queries` | student | Ask a question |
| GET | `/api/queries/mine` | student | My questions |
| GET | `/api/queries/inbox` | teacher | All questions (status filter) |
| POST | `/api/queries/:id/reply` | teacher | Answer, or edit your own answer |
| GET | `/api/queries/summary` | student, teacher | Counts for the dashboards |

## 4. Local Setup & Installation

**Requirements:** [Node.js](https://nodejs.org/) 18 or newer, and MongoDB (local install or a free [MongoDB Atlas](https://www.mongodb.com/atlas) cluster).

**1. Clone and install**
```bash
git clone <your-repository-url>
cd one-for-all
npm install
```

**2. Create the `.env` file** in the project root (the same folder as `package.json`)
```env
PORT=3000
MONGO_URI=mongodb://127.0.0.1:27017/one_for_all
JWT_SECRET=paste-a-long-random-string-of-at-least-32-characters

# Used only by the seed command (step 3). Choose your own temporary passwords.
SEED_ADMIN_ID=ADM0001
SEED_ADMIN_NAME=System Admin
SEED_ADMIN_PASSWORD=choose-a-temporary-admin-password
SEED_SAMPLE_PASSWORD=choose-a-temporary-demo-password
```
Generate a strong `JWT_SECRET` with:
```bash
node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"
```
The server refuses to start if `MONGO_URI` is missing or `JWT_SECRET` is shorter than 32 characters.

**3. Seed the first accounts** (admin plus demo student and teacher)
```bash
node server/seed/seedAdmin.js --with-samples
```
To create only the admin, run `npm run seed:admin`. The seed never overwrites an existing account and never prints a password.

**4. Start the server**
```bash
npm run dev
```
Open **http://localhost:3000**. The same server serves the website and the API.

**5. First sign-in:** open **Login**, pick the role tab, and sign in with a seeded account. You will be asked to choose a new password right away.

## 5. Default Seeded Demo Credentials

Passwords are not hard-coded in the project. They are the temporary values you put in your own `.env`.

| Role | User ID | Temporary password comes from | Created by |
|---|---|---|---|
| **Admin** | `ADM0001` | `SEED_ADMIN_PASSWORD` | `seedAdmin.js` |
| **Student** | `STD0001` | `SEED_SAMPLE_PASSWORD` | `seedAdmin.js --with-samples` |
| **Teacher** | `TEA0001` | `SEED_SAMPLE_PASSWORD` | `seedAdmin.js --with-samples` |

> Every seeded account is flagged **first login**, so the temporary password only works once. After it is used, the user must set a new strong password. Demo users are for testing only and are skipped when `NODE_ENV=production`.

### Quick demo for evaluation
1. Sign in as `ADM0001` and open the Admin dashboard to create or suspend users.
2. Sign in as `STD0001` and ask a question in **Query Portal**.
3. Sign in as `TEA0001`, open **Student Queries** and reply.
4. Sign back in as `STD0001` to see the answer.
